# M0 — аудит перед прогнозом

База: 1.6.1, schema 5, подпись SHA-256 33a740b53e8c553ba665f1fb39cfefe7893ef292ded50d505ff61932658c3c66.
Проверка 22.10.2026: 77/77 unit PASS, build PASS (165075 байт), выполнение скомпилированного NativeBridge PASS. Логи: verification/forecast/M0/.

Приложение — Java Activity/WebView, локальные ES-модули, атомарная запись SharedPreferences. Gradle/Room не используются. Сохраняем эту технологию. Расчёты денег остаются в core.mjs; календарь двух недель и SafeArea не меняются. Прогноз — отдельная часть общей резервной копии, schema 6 с автоматическим чтением 1–5. Старая копия без прогноза не стирает новый раздел.

Источники: ТЗ1.1 в docs/COURIER_FORECAST_AGENT_IMPLEMENTATION_PLAN.md; пользовательский Courier Forecast.xlsx SHA-256 22d256c4534526928ddc8782516404fd5c03e6b0702c85d45dcd29107808402f, только чтение. Персональные данные таблицы не включаются в распространяемый APK.

В XLSX есть независимые дневные итоги, частичный RAW, реконструированные интервалы и формулы без подтверждённых значений. Активные часы таблицы не всегда факт готовности работать. Разрывы заказов не доказывают личную паузу. Снимки периода накопительные: их нельзя складывать с дневными заказами. Импорт прогноза не пишет вознаграждение, чаевые, удержания или почасовые правила: старое определение общего дохода в финансовом листе противоречит принятой формуле приложения.

WORK включает ожидание при готовности и выполняемую доставку; UNAVAILABLE требует подтверждения. Часы Яндекса независимы. План не подтверждает факт. Ручные уточнения и утренние выпуски сохраняются ревизиями. Неполный RAW не обучает почасовые нули.

Android SDK/Java доступны. /dev/kvm отсутствует; реальная проверка MediaProjection/OCR и расхода батареи пока не выполнена. Браузерный тест и JVM-проверка NativeBridge не заменяют такой проверки. M7/M9 нельзя объявлять полным PASS на основании сборки.

Статус M0: базовые технические проверки PASS; независимая проверка и этапы реализации фиксируются отдельно в docs/acceptance/FORECAST_IMPLEMENTATION.md.
