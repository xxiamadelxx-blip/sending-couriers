# Приёмка передачи видеофакта в прогноз

Дата проверки: 2026-10-31\
Статус: **логика импорта и прогнозный расчёт проверены; Android end-to-end приёмка не выполнена**.

## Проверенный путь данных

1. `M4ForecastFactWriter` создаёт дневной JSON-факт видео, включая стабильный `slotId` и число заказов слота.
2. `VideoImportWorker` сохраняет исходные факты в SQLite и передаёт `forecastDay` через `MainActivity` в WebView.
3. `web/app.mjs` передаёт JSON в `importDays` и сохраняет обновлённое состояние.
4. `web/forecast.mjs` хранит видео-слоты отдельно от подтверждённого итога дня. Разные ID слотов суммируются один раз; повтор того же ID идемпотентен. Итог дня из истории сохраняет приоритет. Видео не становится подтверждением рабочего времени.
5. Экранный расчёт выполняется `forecastDay` → текущей локальной моделью прогноза.

## Исправленные случаи

- Раньше импорт одного слота мог сравнить его число заказов с итогом всего дня. Для 13 октября это создавало конфликт `26 против 9` и исключало дату из обучающей выборки.
- Видео-импорт теперь сохраняет 9 заказов как факт отдельного слота, оставляет дневной итог 26, восстановленную экспозицию 481 минуту и отсутствие подтверждения рабочего времени.
- Повторный импорт разных роликов для одного дня суммирует только уникальные ID. Разные числа для одного ID остаются явным конфликтом слота.
- Объединение двух сохранённых состояний переносит слоты без повторного суммирования; если в одном состоянии есть дневной итог, он остаётся итогом дня.
- Повторный импорт книги снимает старый конфликт дневного итога с видео и восстанавливает реконструированную экспозицию.

## Прогон на доступной истории

Импортёр приложения обработал книгу `Courier Forecast`: **55 дневных записей с 2026-08-21 по 2026-10-28**, **1 248 RAW-заказов**. Проверочный прогноз был рассчитан на 2026-10-31 по типичному графику из книги: **600 минут** (09:00–15:00 и 18:00–22:00). Это плановое допущение, не подтверждённый график фактической смены.

| Показатель | Результат |
|---|---:|
| Центральный прогноз на день | 38 заказов |
| Интервал прогноза | 20–60 |
| Уверенность | Низкая |
| Сопоставимых дней | 5 |
| Дней с реконструированными часами в baseline | 5, вес 0,3 |
| Почасовой профиль | Не обучен: недостаточно подтверждённых данных |
| Строгая walk-forward проверка на подтверждённых рабочих днях | `n=0` |

Внутренний отбор baseline имел один сопоставимый проверочный день (`n=1`, MAE 1); строгая отдельная проверка по подтверждённым рабочим дням всё ещё имеет `n=0`. Это не достаточная выборка для заявления о точности.

В прогнозный replay подан JSON payload видео-слота на 9 заказов за 13 октября; это проверка передачи и обработки факта, не повторный OCR-прогон исходного MP4. Прогноз на 31 октября, дневной итог и экспозиция не поменялись; конфликтов не появилось. Значит, путь данных больше не портит обучение, но это само по себе не доказывает точность прогноза.

## Проверки и предел приёмки

- `npm test`: **193/193 JS-теста прошли**.
- `python3 -m unittest discover -s tests -p 'test_*.py'`: **80/80 Python-тестов прошли**.
- Контрактный тест фиксирует наличие ID слота в Android JSON и его передачу в Web import/persist путь.
- В этой среде отсутствуют `adb` и `gradle`; поэтому сборка APK и запуск полного native-потока «выбор видео → Android SQLite → WebView → обновлённый экран» здесь не подтверждены. Нельзя обозначать всю Android-приёмку этапа как закрытую.
- Модель реально считает прогноз по книге, но при текущем наборе доказательств он низкой уверенности. Точность требует появления пригодных подтверждённых дат для независимого backtest; неподтверждённое рабочее время не повышалось до подтверждённого.
