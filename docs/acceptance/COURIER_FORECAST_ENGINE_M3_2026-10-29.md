# M3 — Нативный автономный прогноз числа заказов

**Основание:** M2 PR #5, исходный SHA 947a727b4727cb3c5cc1a6d26692efc5a7bc6d19.  
**Статус:** IN PROGRESS. Этот документ не объявляет M3 принятым до сборки, JVM-проверок и реального запуска probe APK на облачном Android.

## Критерии

| Критерий | Как проверяется | Статус |
|---|---|---|
| Native-модель работает без WebView, сети и генеративного ИИ | Отдельная Android probe Activity обращается только к SQLite и Java-модели | NOT RUN |
| Факт пригоден только при подтверждённом дневном количестве и подтверждённой экспозиции WORK в той же местной дате и зоне | SQLite fixtures: нулевой заказ при наличии WORK сохраняется; количество без WORK, неизвестные и неподтверждённые интервалы исключаются | NOT RUN |
| Знаменатель прогноза — фактическая экспозиция WORK; часы Яндекса и полный слот в движок не передаются | Модельный API принимает только targetWorkMinutes; тест без интервальной экспозиции возвращает недостаточно данных | NOT RUN |
| Baseline, Poisson и Negative Binomial оцениваются walk-forward на одинаковых удержанных датах; будущее не влияет на прошлый прогноз | Фиксированная серия дат, проверки cutoff и одинаковых дат сравнения; выбор кандидата требует не менее 6 matched folds и улучшения MAE не менее 5% | NOT RUN |
| Вывод содержит MAE, bias, WAPE (не определён при нулевой сумме фактов), размер выборки и версию модели | Проверка сохранённой метрики и независимая формула на фикстуре | NOT RUN |
| Опубликованный прогноз, оценка и версия модели неизменяемы | SQLite-триггеры запрещают UPDATE/DELETE; повторная оценка той же ревизии идемпотентна | NOT RUN |
| SQLite v1/v2/v3 переходит к v4 без потери строк | Реальные SQLite migration fixtures и Android upgrade probe | NOT RUN |

## Модель и пределы

- Дневной baseline использует последние 56 пригодных дат, выбирает тот же день недели при наличии трёх или более наблюдений и взвешивает свежесть с периодом затухания 35 дней.
- Нативный Poisson использует подтверждённые WORK hours как exposure offset и отдельный коэффициент дня недели. Negative Binomial допустим только при минимум 28 подтверждённых датах, сумме не менее 200 заказов, dispersion > 1,3 и оценке alpha > 0,05. Ни один кандидат не заменяет baseline без заранее заданного порога walk-forward.
- Нулевой счёт — реальный факт только при положительном подтверждённом WORK-интервале. Неизвестные, реконструированные, конфликтные и отсутствующие интервалы не превращаются в ноль.
- Экспозиция собирается из подтверждённых интервалов с ISO-временем; длительности пересекаются по реальным временным отрезкам и разбиваются по местной дате. Часы выплат, legacy_slot_facts, RAW-число заказов и погода в этой версии не подменяют экспозицию.
- Интервал показан как номинальный 90% predictive interval; это не утверждение, что на личной истории уже измерено 90% покрытие.
- Текущий M3 endpoint публикует нативный snapshot и оценивает завершённый день. Экран прогноза, планировщик недели и выполнение после остановки процесса относятся к следующим этапам.

## Приёмка

Успешная сборка или JVM-тест сами по себе не подтверждают Android runtime. Финальный статус каждого критерия будет привязан к commit SHA, команде/Workflow run, APK SHA-256 и скриншоту реального cloud Android. Пользовательская XLSX-книга и личные факты в fixtures или APK не копируются.
