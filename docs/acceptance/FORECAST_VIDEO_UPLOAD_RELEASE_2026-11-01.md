# Видео → прогноз: релизный аудит

Дата: 2026-11-01  
Ветка: `release/forecast-video-upload-20261101`  
Состояние: APK 1.7.16 собран и подписан; GitHub Actions run 77 завершился успешно. Для полного пользовательского выпуска осталось проверить исходный MP4 на Android-устройстве и принять решение по публикации.

## Состав релизной ветки

Ветка основана на `m4/continuous-video-multislot-20261031` и сохраняет предшествующие M2–M6 изменения. В неё сведены загрузка MP4/MOV, локальный разбор видео, многослотовый парсер, сверка с историей и экран прогноза. M7-захват экрана не включён: основной поток запускает выбор файла и импорт видео. Google Sheets OAuth/синхронизация тоже не включены.

Сборка: `ru.courier.finance.transfer`, версия `1.7.16`, `versionCode 30`. В Actions собираются тестовая QA-сборка и отдельный unsigned APK transfer-пакета. Приватный ключ в репозиторий и Actions не передаётся; финальный APK подписывается локально существующим ключом владельца. Его сертификат проверен по SHA-256 отпечатку предыдущей версии transfer-пакета.

## Что уже реализовано

- M2: SQLite shadow store и проверки контракта миграции при сохранении прежнего JSON как источника состояния.
- M3: native count model и восстановление подсчёта при перезапуске.
- M4: Android выбор/загрузка видео, локальная выборка кадров и OCR на встроенных русской и английской моделях.
- Непрерывное видео: парсер связывает строки с ID слота, различает вечерний и утренний слоты и объединяет только уникальные слоты.
- M5: согласование видеофактов с историей и RAW-заказами; повторный импорт идемпотентен, дневной итог из истории имеет приоритет, время работы из видео не подтверждается.
- M6: сохранение прогноза и фоновые задачи восстановления/оценки.
- Экран прогноза: сегодня, неделя, история и точность; импортированный факт после обработки передаётся из native worker в WebView и сохраняется в модели прогноза.
- Локальный replay пользовательского видео дал 31/31 строки заказа для двух слотов, сумма 3 100 ₽ и чаевые 60 ₽. В replay передано 31 evidence-строка, конфликтов 0. Это desktop OCR и проверка модели, а не Android end-to-end прогон того же ролика.

## Проверки и пределы доказательств

В GitHub Actions run 77 пройдены 194/194 JS-теста, 39/39 Python-контрактных тестов M2–M5, native count model, Android unit tests, сборки QA/transfer APK и Android 35 emulator probe. На предыдущем непрерывном-video replay также зафиксированы 80/80 Python-тестов. Эмуляторный прогон прошёл M4 write, continuous two-slot, M5 reconciliation, M4 restart и M6 offline/restart/reboot/app-open catch-up сценарии. В CI проверены package/version transfer APK; финальная подпись локально прошла по сертификату предыдущей версии.

Прогноз считается рабочим вычислительно, но статистическая точность пока не доказана: по имеющемуся набору оценка на 2026-10-31 была 38 заказов, диапазон 20–60, низкая уверенность, 5 сопоставимых дней; строгий walk-forward backtest на подтверждённых часах имеет n=0. Неопределённые/реконструированные часы не повышаются до подтверждённых.

## Что осталось до полного выпуска

1. Установить APK на Android, выбрать реальное видео Яндекс Про, сравнить распознанные слоты и число заказов с исходником, проверить обновление прогноза и сохранение результата после перезапуска. CI проверил native-путь на синтетическом видео; локальный replay реального видео был desktop OCR, поэтому это последняя обязательная пользовательская приёмка.
2. После приёмки влить эту ветку в `main` и выполнить выбранную публикацию. Сейчас создана релизная ветка-кандидат; `main` и магазины не изменялись.
3. Для заявлений о точности накопить подтверждённые рабочие часы и провести walk-forward backtest. Это не мешает расчёту прогноза, но до этого уверенность модели должна оставаться низкой.

## Зафиксированные решения

- Сборка и QA — GitHub Actions, один полный прогон. Codemagic не используется.
- Не запускать дополнительные Vercel/CircleCI проверки для Android APK.
- Захват экрана исключён из релизного потока; импорт запускает пользователь через выбор видео.
