# Инструкции проекта

- Пользовательская цель — готовый Android APK. Работу выполнять в текущей облачной сессии, без перевода задачи в Codex Cloud и без требования физического ПК пользователя.
- Продуктовые требования и три макета находятся в `design/`. Прямые последующие инструкции пользователя имеют приоритет над прежними запретами на выпуск APK.
- Все финансовые формулы держать в `web/core.mjs`. Денежные поля раздельные; налог и комиссия не выводятся отдельными строками сводки, истории или Markdown.
- Вознаграждение 0 допустимо. Часы и заказы вводятся за слот/запись; при одном слоте допустим итог дня, необязательны независимо друг от друга. Пропуски хранить как неизвестные. Сводка складывает все введённые дневные значения периода; редактирование и удаление по id затрагивают только выбранную запись. Монотонность между днями не требуется.
- Темп и запас считать по суммам введённых часов и заказов периода, даже если даты с заполненными полями различаются. Не исключать часы дня без заказов и не скрывать весь расчёт из-за пропуска одной ячейки. При несовпадающих наборах дней показывать краткое пояснение, что это оценка по введённым итогам; null не заменять нулём в данных. Если нет ни одного числа заказов или сумма часов нулевая, темп и запас остаются неопределёнными. Регрессия отчёта 13.10.2026: 120 ч, 217 заказов, пустые заказы за 10 октября дают 1,808 заказа/ч и 33 минуты запаса.
- Формат 3 использует устойчивый id и допускает несколько записей на дату. Форматы 1/2 читаются автоматически с устойчивым id по исходной дате; новые слоты получают отдельный id. Повторный импорт формата 3 заменяет совпадающие id и не дублирует слоты. Старый дневной импорт обновляет соответствующую прежнюю запись, не затрагивая новый слот за ту же дату; неоднозначный старый итог не применять автоматически. Перенос накопительных интервалов заменяет записи по id, не по дате.
- Формат 2 использует dailyHours (до двух десятичных знаков) и dailyOrders. Формат 1 и незавершённый формат 2 читаются автоматически, без выбора переноса и блокирующего баннера. По умолчанию прежние значения дневные; возрастающие часы больше 24 распознаются как накопительные и преобразуются в разницы. Уже сохранённые вклады дней и ручные исправления не менять. Исходные показания и деньги сохранять. Накопительный интервал не называть точной сменой за один день.
- При вводе показывать ориентиры: налог 4–6% от вознаграждения, комиссия парка 5%, округление до копейки. Расхождения — только предупреждения, никогда не блокировать сохранение из-за процента. Фактические введённые суммы сохранять без замены; удержания необязательны. Неверный числовой формат проверять отдельно. Предупреждения не вычитать повторно из выплат и не менять формулы дохода.
- Не добавлять снимки из макетов в пользовательскую базу. Перед реальной миграцией данных использовать только доступный и разрешённый источник.
- Русский интерфейс, автономная работа, устойчивая локальная запись. Не добавлять сетевую или платную зависимость.
- Проверять добавление задним числом, исправление, удаление, независимость периодов и автоматическое чтение обоих прежних форматов. Не повторять перенос при чтении уже преобразованных данных. Ручные исправления после переноса сохранять.
- Кнопка сохранения находится вне прокручиваемых полей; поля и клавиатура не должны перекрываться.
- Нативный writeState должен принимать актуальный schemaVersion=5 и прежние 1/2/3/4. После сборки запускать tests/verify_native.py: выполнение реального скомпилированного NativeBridge с тестовым вводом, а не только браузерной подменой.
